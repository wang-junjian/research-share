# 管理员任命权收归初始管理员独占

原设计里任何管理员都能任命或移除管理员（`admins` 表 INSERT/DELETE 的 RLS 策略仅判 `is_admin()`），这意味着你任命的第一个管理员就能把你移除，之后无人能制约他。我们决定引入「初始管理员（Founder Admin）」身份：全站唯一、不可经正常途径移除，独占管理员任命权——提升录入者、降级管理员都只有初始管理员能做。普通管理员保留对全部研究成果与数据看板的管理能力，但不再能碰 admins 名单。

## Considered Options

- **维持现状：任何管理员都能任命/移除管理员**：拒绝。任命权一旦下放就无法收回——被任命者可以先下手移除任命人。小团队信任圈也不能把「谁能管人」建立在对每个未来管理员的无限信任上。
- **环境变量/配置文件指定初始管理员**：拒绝。身份是数据，应与 `admins` 表同住数据库；配置与数据两张皮会让 RLS 判定依赖部署环境，换环境还要重新对一遍。
- **管理员任命需多人同意（投票/双签）**：拒绝。两个人就能完成的小团队，治理机制是过度设计；真出问题，初始管理员直接降级即可。

## Consequences

- `admins` 表新增 `is_founder boolean` 列；`is_founder = true` 全站唯一（部分唯一索引），且 founder 行不可经 RLS DELETE 策略删除（含 founder 本人，防手滑）。
- `admins` 表的 INSERT/DELETE 策略从「仅管理员」收窄为「仅初始管理员」；`is_admin()` 语义不变，成果与看板的权限不受影响。
- 后台 UI：普通管理员看不到「设为管理员」「移除」按钮；角色标签区分「初始管理员」/「管理员」。真正的边界仍在数据库层，UI 只是不挑逗。
- 初始管理员身份不可自我放弃，也不提供 UI 转让。交接是罕见操作，走一次性手工 SQL（把接任者置 `is_founder = true`、自己置 `false`）。
- 初始管理员的 user_id 经迁移脚本 seed（`db/05`），取代 db/01 末尾「手工取消注释」的种子步骤，「初始只有我」从此可复现。
